Format berkas ini mengacu pada prinsip [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) dan mematuhi [Semantic Versioning](https://semver.org/).

## [1.7.2] - 2026-11-05

Rilis perbaikan untuk katalog model Antigravity (B-157): gateway kini menyelesaikan project Code Assist akun lewat `loadCodeAssist` — disimpan per sesi OAuth (migrasi baru `0023`), diselesaikan sesudah exchange dan secara malas pada pemakaian sesi sehingga **login yang sudah ada sembuh tanpa login ulang** — lalu meneruskannya ke `fetchAvailableModels` dan amplop generate/stream, sehingga model tergating-project yang terlihat di aplikasi Antigravity/agy milik akun yang sama (mis. "Argon") bisa masuk katalog Route-X. Sync model juga menangkap `displayName` upstream. **OpenAI Codex CLI masih berlabel sementara tidak-didukung** menunggu keputusan B-153 (dukungan streaming Responses API). Jalur upgrade dari v1.7.1 lurus: pasang biner baru dan migrasi `0023` diterapkan otomatis saat biner mulai; sesudah upgrade, satu klik sync model pada provider Antigravity menyelesaikan project sesi yang ada.

### Fixed

- **Model Antigravity tergating-project kini bisa terlihat (B-157)**: gateway tidak pernah menyelesaikan project Code Assist akun — `loadCodeAssist` tidak pernah dipanggil, `fetchAvailableModels` selalu diminta dengan body kosong, dan amplop generate/stream membawa `"project": ""` — sehingga katalog Antigravity hanya berisi himpunan generik dan model per-project (mis. model yang tampil sebagai "Argon" di agy milik akun yang sama) tidak pernah muncul. Kini project Code Assist diselesaikan sesudah exchange OAuth dan secara malas pada pemakaian sesi (sinkronisasi model serta konstruksi adapter di factory), disimpan per sesi (migrasi `0023`), lalu diteruskan ke body `fetchAvailableModels` dan field `project` pada amplop generate/stream. Kegagalan resolusi tidak menggagalkan alur utama: perilaku generik tanpa project berlanjut dan kegagalannya tercatat di log. Sinkronisasi model juga kini menangkap `displayName` upstream ke katalog — nama model bukan lagi ID mentah; nama yang sudah diatur operator tidak ditimpa.

## [1.7.1] - 2026-11-05

Rilis perbaikan ini memulihkan tombol Hubungkan Antigravity yang mati di instalasi yang tidak menyetel env: client secret aplikasi desktop Google kembali tertanam sebagai **cadangan otomatis** dan `ANTIGRAVITY_CLIENT_SECRET` menjadi penimpa opsional — sebuah **pembatalan sadar atas B-036** (audit3 grup 8), diputuskan pemilik karena nilai client aplikasi desktop bersifat non-rahasia menurut desain OAuth installed-app Google (identitas aplikasi, bukan pengaman akun); lihat entri B-156 di bawah dan `BACKLOG-FIX.md`. Rilis ini juga menghimpun **rombakan registri CLI** (PR #272–#275): registri final 11 tool — 12 entri mati/berlabel dicabut, 6 tool baru ditambahkan, 5 di antaranya terbukti live; **OpenAI Codex CLI masih berlabel sementara tidak-didukung** menunggu keputusan B-153 (dukungan streaming Responses API). Tidak ada migrasi skema baru (tetap 22). **Catatan akses:** atas keputusan pemilik, repositori Route-X kini bersifat **private** — unduhan aset rilis tidak lagi anonim dan memerlukan autentikasi GitHub; panduan instalasi publik tidak lagi berlaku bagi publik. Jalur upgrade dari v1.7.0 lurus: jalankan ulang installer (dengan akses terautentikasi ke rilis) dan migrasi diterapkan otomatis saat biner mulai.

### Changed

- **Client secret Antigravity: cadangan tertanam dipulihkan, env menjadi penimpa opsional (B-156 — membatalkan B-036 secara sadar)**: sejak audit3 grup 8, client secret Antigravity wajib datang dari env `ANTIGRAVITY_CLIENT_SECRET` dan ketiadaannya menggagalkan tombol Hubungkan sebelum login Google (terbukti pada instalasi produksi, 5 Nov 2026). Nilai client aplikasi desktop Google ini bersifat non-rahasia menurut desain OAuth installed-app (beredar di setiap salinan aplikasi; fungsinya identitas aplikasi, bukan pengaman akun), sehingga biner kini kembali membawa nilai bawaan itu sebagai **cadangan otomatis tanpa obfuskasi**: resolusi secret untuk penukaran kode DAN refresh sesi adalah env non-kosong bila terisi, selain itu cadangan tertanam. `ANTIGRAVITY_CLIENT_SECRET` tetap didukung penuh sebagai penimpa (mis. bila Google merotasi client-nya); dokumentasi konfigurasi (README, SECURITY, panduan deploy) diselaraskan menjadi "opsional-penimpa".
- **Klaim provisioning CLI di README diperbaiki (B-155)**: README kini menyatakan provisioning sekali klik berlaku untuk 10 dari 11 tool CLI terdaftar, dan OpenAI Codex CLI dinyatakan terdaftar serta terdeteksi tetapi belum dapat dikonfigurasi karena gateway belum mendukung Responses API streaming — menggantikan klaim lama bahwa ke-11 tool dapat di-provisioning dan dikonfigurasi dengan cara yang sama, selaras dengan status sementara Codex (B-153).
- **Kejujuran registri CLI (Tahap 3 — B-153, B-149, B-154)**: **OpenAI Codex CLI kini berstatus sementara tidak-didukung** — uji live membuktikan Codex hanya berbicara Responses API dengan streaming (`stream: true`) sedangkan `/v1/responses` gateway baru mendukung non-streaming, sehingga permintaan pertamanya mati `400 streaming_not_supported`. Configure Codex kini DITOLAK dengan alasan itu (B-153) sampai dukungan streaming Responses tiba, alih-alih mengklaim berhasil untuk tool yang mati di permintaan pertama; penulis `~/.codex/config.toml` dipertahankan agar jalur Configure hidup lagi begitu alasannya dicabut. Registri tetap 11 entri: 10 didukung + Codex beralasan sementara. Deskripsi **Cline** kini menyatakan konfigurasinya disimpan dan dikelola store internal CLI Cline sendiri lewat perintah resmi `cline auth` — statusnya dikelola tool itu, bukan berkas Route-X (B-149) — dan deskripsi **Hermes Agent** serta **Cline** kini mencatat jalan headless-nya dapat meninggalkan daemon latar yang perlu dimatikan operator (B-154).

### Added

- **Enam tool CLI baru di registri Integrasi CLI** (perombakan registri Tahap 1), masing-masing dikonfigurasi lewat format resmi yang terverifikasi dari dokumentasi/repo upstream-nya: **OpenAI Codex CLI** (`~/.codex/config.toml` — provider `routex` dengan `wire_api = "responses"` dan `env_key = "OPENAI_API_KEY"`; Codex tidak lagi mendukung chat completions), **Grok Build** (`~/.grok/config.toml` — `[model.routex]` dengan `env_key = "XAI_API_KEY"`), **Qwen Code** (env `OPENAI_*` resmi + `~/.qwen/settings.json`), **Crush** (`~/.config/crush/crush.json` — provider `openai-compat`), **Hermes Agent** (blok `model:` provider `custom` di `~/.hermes/config.yaml` + kunci di `~/.hermes/.env`), dan **Cline CLI** (Configure menjalankan perintah resmi `cline auth` dari CLI itu sendiri; gagal jujur bila biner tidak terpasang).

### Removed

- **BREAKING — 12 tool CLI dicabut total dari registri Integrasi CLI**: `agy`, `cursor-agent`, `cody`, `plandex`, `ollama`, `continue`, `sgpt`, `fabric`, `llm`, `opencommit`, `chatblade`, dan `k8sgpt`. Registri kini tepat 11 entri (Claude Code, OpenCode, OpenAI Codex CLI, Grok Build, Qwen Code, Crush, Hermes Agent, Cline, Aider, Goose, GitHub Copilot CLI) — hanya CLI terkemuka, stabil, dan berkomunitas besar yang dipertahankan/ditambah. Configure untuk id yang dicabut kini menjawab tidak dikenal; preferensi tersimpan `cli:config:<id>` milik id tercabut dibersihkan saat pemuatan tanpa menyentuh preferensi tool yang bertahan.

## [1.7.0] - 2026-11-04

Rilis ini menghimpun seluruh pekerjaan sejak v1.6.1: permukaan `/v1/responses` menjadi OpenAI Responses API asli (B-105 — memuat **perubahan BREAKING perilaku**, lihat Added), peran pengguna menjadi data sungguhan (B-102 — **BREAKING perilaku** untuk pembuatan pengguna tanpa peran admin), seluruh toggle admin kini menuntut field `enabled` eksplisit (B-088 — **BREAKING perilaku**), UI harga per pemetaan beserta endpoint katalog harga acuan global, halaman Log Audit di dashboard, pengerasan gateway (penegakan anggaran yang benar-benar efektif B-106, error kandidat yang jujur B-111/B-120/B-143, kredensial/provider nonaktif benar-benar menghentikan trafik B-103), perbaikan keluaran Configure CLI dan kejujuran katalog integrasi (registri kini 17 tool), perbaikan installer (B-084, B-095, B-104), dan kenaikan toolchain web terkoordinasi (Vite 8, React 19, Recharts 3). Tiga migrasi skema baru: `0020` (kolom peran pengguna), `0021` (riwayat delivery webhook dilepas dari induknya), `0022` (kolom deskripsi egress berfungsi ujung-ke-ujung + peristiwa timeline `cache_hit`). Jalur upgrade dari v1.6.1 lurus: jalankan ulang installer; migrasi diterapkan otomatis saat biner baru mulai.

### Added
- **Filter aktor dan `limit` pada daftar log audit (B-139)**: `GET /api/admin/system/audit-logs` kini membaca parameter `actor_user_id` — lapisan repo (`AuditFilter.ActorUserID`, termasuk validasi UUID-nya) sudah lama mendukung penyaringan per pelaku dan teruji, tetapi handler tidak pernah menghubungkannya, jadi pertanyaan audit paling umum ("siapa melakukan ini") tidak terjangkau lewat API. Parameter `limit` pada handler yang sama juga kini dihormati mengikuti pola endpoint daftar lain (bawaan 50, dijepit `MaxPageLimit` 500 oleh `repo.Page.Normalize`); sebelumnya ukuran halaman selalu keras 50. OpenAPI diperbarui untuk kedua parameter. Satu perbaikan searea yang ikut terbawa: nilai `actor_user_id` yang bukan UUID kini dijawab 400 oleh handler — sentinel `identity.ErrInvalidInput` dari repo tidak dikenal `mapRepoError` dan akan tersaji sebagai 500 bila handler meneruskannya mentah. Halaman Log Audit di dashboard kini menawarkan filter ID aktor yang nyata ini (lihat PR pendamping web).
- **Sub-field `thinking` tak dikenal diteruskan setia ke upstream Anthropic (B-137)**: terverifikasi dengan test penangkap body upstream bahwa sub-field thinking selain `type`/`budget_tokens` — mis. `display` dari klien Claude Code modern — sebelumnya terbuang diam-diam saat decode permukaan `/v1/messages` (bentuk kanonik hanya menyimpan dua field yang dikenal, dan body yang diteruskan ke upstream tiruan Anthropic pun hanya memuat keduanya). Decode kini mempertahankan sub-field lain mentah (`ThinkingParam.Extra`) dan adapter Anthropic menggabungkannya kembali ke blok `thinking` upstream apa adanya, untuk `enabled` maupun `adaptive`. Untuk upstream non-Anthropic, sub-field itu dibuang bersama seluruh parameter thinking — konsisten dengan perlakuan B-096 dan kini terdokumentasi di `providers.ThinkingParam`: upstream itu tidak punya konsep thinking bergaya Anthropic sehingga tidak ada padanan setia yang bisa dikirim.
- **Endpoint katalog harga acuan global (B-090)**: `GET /api/admin/upstreams/models/pricing/reference-catalog` (izin `models:read`, terdaftar di OpenAPI) mengembalikan SELURUH harga acuan bawaan yang dikenal sistem dari satu-satunya sumbernya (`seed.ReferencePrices`) beserta field `note` yang menyatakan cakupannya apa adanya — himpunan acuan kecil yang asal angkanya tercatat, **bukan katalog harga pasar**; model tanpa entri di sini tetap tidak punya acuan yang bisa dipertanggungjawabkan. Konversi DTO kini satu jalur bersama dengan endpoint acuan per-pemetaan (B-075/Langkah 4) supaya angka dan asal yang ditampilkan tidak bisa berbeda antar-endpoint. Metode klien web `api.models.pricingReferenceCatalog()` ikut ditambahkan; drawer Harga per-pemetaan tetap memakai endpoint per-pemetaan dari sumber yang sama (kontraknya memang per-pemetaan), jadi tidak ada tabel katalog global baru di UI — sisa penghubungan UI dinyatakan eksplisit di entri backlog B-090. Catatan pada entri UI harga di bawah ("tidak ada tabel katalog acuan global") ditulis sebelum endpoint ini ada dan kini dilengkapi entri ini.
- **Metadata lifecycle model dari discovery upstream kini dipertahankan (B-089)**: sinkronisasi model tidak lagi membuang field lifecycle yang BENAR-BENAR dikirim upstream. Untuk discovery OpenAI-compatible, `status`/`shutdown_date`/`replacement_model` (bentuk yang terbukti dikirim Intern-AI) disimpan ke `models.metadata` sebagai `lifecycle_status`/`lifecycle_shutdown_date`/`lifecycle_replacement_model`/`lifecycle_source: upstream_discovery` — terlihat lewat API daftar model yang memang sudah mengekspos `metadata` dan `deprecated_at` — dan model yang statusnya menandai akhir masa (deprecated/shutdown/sunset/retired/dsb. atau mempunyai tanggal shutdown) ditandai `deprecated_at` pada saat sync. **Keputusan eksplisit: penandaan saja, TIDAK ada penonaktifan otomatis** — gateway tetap melayani model itu dan operator yang memutuskan. Model yang sudah ada hanya diperbarui metadata/`deprecated_at`-nya (kapabilitas dan nama hasil pengaturan operator tidak ditimpa). Keluarga upstream yang tidak menyediakan metadata lifecycle pada respons discovery-nya (Google, Ollama, Antigravity, katalog fallback terkurasi) tetap tanpa penanda — gateway tidak mengarang status untuk mereka.
- **Peristiwa timeline `cache_hit` untuk request yang terjawab dari cache (B-116 butir 7, migrasi `0022`)**: request cache HIT sebelumnya tidak mempunyai baris `request_events` sama sekali (tidak ada percobaan upstream untuk dicatat), sehingga tab Events inspektor tampil kosong tanpa penjelasan. Kini ketiga permukaan (Chat Completions, Anthropic Messages, Responses) menandai HIT pada jejak pemakaian dan pencatat menulis satu peristiwa `cache_hit` yang menyatakan respons dilayani dari response cache tanpa panggilan upstream.
- **Kolom `description` egress pool kini berfungsi ujung-ke-ujung (B-116 butir 1, migrasi `0022`)**: `egress_pool.description` sebelumnya ada di skema dan diterima request buat/ubah, tetapi tidak pernah disimpan maupun dikembalikan — DTO tidak memuatnya sama sekali. Kini kolomnya disimpan saat buat, bisa diubah lewat PUT (membedakan field absen dari string kosong), dikembalikan di `EgressPoolDTO`, dan dashboard mempunyai field Deskripsi pada drawer buat/edit egress serta menampilkannya di kartu pool.

- **Halaman Log Audit di dashboard (B-108)**: menu **Sistem & Pengaturan → Log Audit** (rute `/system/audit-logs`, juga tersedia lewat palet perintah) kini menampilkan jejak audit administratif yang sebelumnya hanya bisa dibaca lewat API mentah, padahal endpoint `GET /api/admin/system/audit-logs` dan klien web-nya sudah lama ada tanpa satu pun komponen UI yang mengonsumsinya. Halaman mengikuti pola daftar yang ada: filter rentang waktu (24 jam / 7 hari / 30 hari / semua waktu — pilihan terakhir mengirim `from` eksplisit agar bawaan 24 jam backend tidak menyamar sebagai "semua"), filter kecocokan persis untuk aksi dan jenis sumber daya, paginasi kursor "Muat Lebih Banyak", dan detail satu catatan (aktor, IP, ID permintaan, user agent, metadata) lewat drawer. Filter yang ditawarkan persis yang didukung handler-nya — saat halaman ini pertama dibangun handler belum membaca filter aktor maupun `limit`, jadi UI tidak mengarangnya; kesenjangan handler itu dicatat sebagai entri backlog tersendiri dan ditutup B-139, yang sekaligus menambahkan filter aktor ke halaman ini. Keadaan loading, error (dengan Coba Lagi), dan kosong ditampilkan apa adanya dan dibedakan satu sama lain.
- **Saklar enable/disable provider di halaman Penyedia (B-086)**: kartu provider kini mempunyai saklar status (pola saklar yang sama dengan kartu aturan perutean) yang memanggil rute toggle resmi provider dengan badan `{enabled}` eksplisit — kontrak B-088, klien wajib mengirim nilai tujuan. Sebelumnya endpoint dan metode klien `api.providers.toggle` sudah terbukti ada tetapi tidak pernah dipanggil UI mana pun, sehingga operator harus memakai API/SQL untuk menonaktifkan provider. Status tampil apa adanya dari data, saklar terkunci selama permintaan berjalan, dan kegagalan tampil sebagai toast error yang menyebut sebabnya.
- **UI harga per pemetaan model di dashboard**: drawer **Harga** pada setiap pemetaan di tab Model provider (halaman Penyedia) kini menampilkan tiga hal yang selama ini hanya bisa diakses lewat API — (1) **harga efektif** yang sedang menagih, diturunkan dari riwayat harga dengan predikat rentang efektif yang sama dengan backend; (2) **harga acuan (reference)** katalog bawaan untuk pemetaan itu beserta sumber dan tanggal ambilnya, dinyatakan jelas sebagai tawaran awal yang tidak menagih; dan (3) **formulir pasang harga manual** yang menulis lewat endpoint `POST /api/admin/upstreams/models/mappings/{id}/pricing` yang sudah ada (tombol "Pakai harga acuan sebagai isian" hanya mengisi formulir — pemasangan tetap keputusan operator). Keadaan jujur ditampilkan apa adanya: pemetaan tanpa harga berlaku dinyatakan tercatat *unpriced*, dan pemetaan tanpa acuan katalog dinyatakan tidak punya acuan yang bisa dipertanggungjawabkan (gateway tidak mengarang angka). Tidak ada endpoint backend baru: reference hanya tersedia per-pemetaan dari backend, jadi tidak ada tabel katalog acuan global.
- **`/v1/responses` kini permukaan OpenAI Responses API asli (B-105, subset non-streaming)** — sebelumnya rute ini alias Chat Completions yang menuntut `messages` dan membalas `chat.completion`. Sekarang body `{model, input, instructions, tools, ...}` diterjemahkan ke perancah kanonik gateway (resolusi model, anggaran, rute, penyaring, response cache bercakupan permukaan sendiri) dan jawabannya objek `response` yang benar (`resp_…`, `output[]` berisi item message/`output_text`/`function_call`, `usage {input_tokens, output_tokens, total_tokens}`, status `incomplete` + `incomplete_details` untuk jawaban terpotong). Didukung: input string/items (message, function_call, function_call_output), tools bentuk datar termasuk `strict`, `tool_choice`, `max_output_tokens`, `reasoning.effort`, `text.format`. **Ditolak eksplisit 400**: `stream: true` (kode `streaming_not_supported`), `previous_response_id`, `item_reference`, part `input_file`, `tool_choice: allowed_tools` — streaming Responses dan respons tersimpan adalah pekerjaan lanjutan, bukan diam-diam dialiaskan. **BREAKING (perilaku)**: klien yang selama ini mengirim bentuk chat-completions ke `/v1/responses` kini ditolak; pakai `/v1/chat/completions` untuk bentuk itu.

### Fixed
- **Regresi B-144 diperbaiki: Configure OpenCommit kini menulis anggaran token yang koheren, termasuk `OCO_TOKENS_MAX_INPUT=16384` (B-147)**: terbukti pada Uji Live Putaran 2 bahwa perbaikan B-144 di bawah (plafon keluaran/reasoning 4000 tanpa menaikkan input dari bawaan tool 4096) membuat OpenCommit gagal **lokal pada setiap commit untuk setiap model** — rumus tool 3.3.11 menghitung anggaran request sebagai `OCO_TOKENS_MAX_INPUT − 20 − prompt awal − maxOutput`, yang menjadi negatif, sehingga tool melempar "Token limit exceeded…" dan menampilkannya ke pengguna sebagai pesan "Insufficient Credits" yang menyesatkan; tak satu pun request mencapai gateway. Configure kini juga menulis **`OCO_TOKENS_MAX_INPUT=16384`** di `~/.opencommit` dan EnvVars: nilai itu terverifikasi live sebagai kontrafaktual pada Putaran 2 (dengan 16384 oco benar-benar mencapai gateway) dan hitungannya menyisakan ±12 ribu token ruang diff per request sesudah prompt awal dan plafon. Plafon keluaran/reasoning **tetap 4000** — dasar pemilihan B-144 tidak berubah, dan kelambatan reasoning upstream pada prompt oco adalah karakteristik upstream, bukan alasan menurunkannya. Test regresi kini memeriksa **koherensi hitungan ketiganya** (input − 20 − margin prompt awal − plafon harus menyisakan ruang diff positif yang wajar untuk jalur keluaran maupun reasoning, dan ketiga nilai di berkas harus sama dengan EnvVars), bukan sekadar kehadiran variabel.
- **Versi sgpt kini benar-benar terbaca: timeout deteksi versi dinaikkan 1500 ms → 5 detik (B-148)**: mekanisme kunci tersimpan B-145(a) terbukti bekerja, tetapi `GET /api/admin/cli/detected` tetap mengembalikan versi sgpt kosong pada Uji Live Putaran 2 — sebab terukurnya adalah batas 1500 ms di deteksi versi, lebih kecil dari waktu start nyata `sgpt --version` berkunci (konsisten 1,66–1,68 detik; startup Python tool itu memang lebih lambat dari batas lama). Batas kini **5 detik, berlaku sama untuk semua tool** (bukan pengkhususan sgpt) dan tetap batas keras: biner yang menggantung tetap terpotong padanya (terbukti test biner palsu lambat 2 detik terbaca versinya dan biner menggantung terpotong pada batas baru). Biaya total tertahan: hasil deteksi tetap ditahan cache 5 menit, dan deteksi versi di `Scan` kini berjalan **paralel terbatas (maksimal 8 proses serentak)** — tanpa itu, waktu pindaian terburuk sekuensial akan melonjak dari ±20×1,5 detik menjadi ±20×5 detik; dengan paralel terbatas ia tertahan di ±3 gelombang × 5 detik, di bawah waktu terburuk lama.
- **Deteksi versi chatblade dikembalikan: `VersionArg: "--version"` (B-146)**: pencabutan pada B-145(b) di bawah dibalik untuk entri ini saja berdasarkan bukti Uji Live Putaran 2 yang tuntas — build resmi chatblade **0.7.0** (pip di venv Python 3.13; rilis resmi 0.4–0.7.0 memang mengimplementasikan `--version` di kode resminya) menjalankan `chatblade --version` dengan exit 0 dan stdout persis `chatblade 0.7.0`, sedangkan build terpasang Putaran 1 yang menolak flag itu terbukti bukan rilis resmi. Instalasi chatblade resmi kini tampil berversi di `/detected`; build lama yang menolak flag tetap tampil kosong secara jujur karena deteksi menelan kegagalan perintah versi. Test biner palsu yang mencetak persis keluaran build resmi (`chatblade 0.7.0`) membuktikan versi itu terbaca parser versi produk.
- **Semua provider pemetaan dinonaktifkan kini terjawab jujur `provider_disabled`, bukan `no_provider_for_model` (B-143) — perubahan kontrak error**: terbukti pada Uji Live Putaran 1 bahwa model yang satu-satunya provider pemetaannya berstatus `enabled=false` menjawab 503 `no_provider_for_model` ("tidak ada provider yang dikonfigurasi"), padahal providernya ada dan terkonfigurasi penuh — hanya nonaktif — sehingga operator diarahkan memeriksa konfigurasi yang sebenarnya benar. Mekanisme diagnosa kandidat (B-111/B-120) kini punya cabang ketiga: bila query kandidat biasa dan query `IncludeUnhealthy` sama-sama kosong tetapi query diagnosa baru `IncludeDisabled` pada `RouteCandidates` menemukan pemetaan, gateway menjawab **503 `provider_disabled`** dengan pesan yang menyebut semua provider/pemetaan dinonaktifkan dan obatnya (aktifkan kembali salah satunya). Query diagnosa memakai SQL terpisah yang hanya berjalan pada jalur kandidat kosong — query kandidat terpanas dan indeks parsial routing-nya tidak berubah bentuk. ## [v1.2.0] - 2026-09-21

Rilis yang menghapus integrasi Xray-core secara menyeluruh (#37) beserta
tindak lanjut hardening (#38). Keputusan diambil berdasarkan audit
risiko/manfaat di deployment produksi: integrasi Xray hanya memberi 1 manfaat
(egress SOCKS5) namun mendominasi banyak risiko (open proxy, permukaan
serangan, kompleksitas operasional, titik gagal tunggal). Egress pool generik
(HTTP/HTTPS/SOCKS5) dipertahankan penuh — proxy pihak ketiga (Cloudflare
Gateway, BrightData, VPS sendiri) tetap dapat dipakai tanpa Xray.

### ⚠️ BREAKING CHANGES

- **Env `XRAY_BRIDGE_HOST` dihapus** dari config; tidak lagi dibaca saat boot.
  Env lama pada deployment yang ada diabaikan tanpa error (aman), tapi sebaiknya
  dibersihkan dari `.env`/`docker-compose` deployment masing-masing.
- **Service `xray` dihapus dari `docker-compose.yml`** dan `deploy.sh` tidak
  lagi menjalankannya. Deployment Docker harus `docker compose down` sebelum
  upgrade untuk menghindari container yatim.
- **`install-native.sh` tidak lagi memasang xray-core** dari upstream
  `XTLS/Xray-install`. `xray.service` pada host native yang dipasang sebelumnya
  menjadi yatim — nonaktifkan manual: `systemctl disable --now xray`.
- **Migration `0013_drop_xray_settings.sql`** menghapus record `settings` key
  `system:xray:config`. Tabel `egress_pool` dan `domains` **tidak disentuh**.

### Removed

- **Integrasi Xray-core dihapus seluruhnya** dari kode dan artifak deployment:
  paket `internal/xray/` (orchestrator + config generator VLESS Reality),
  `deploy/xray/`, `deploy/systemd/xray.drop-in.conf`, service `xray` di
  `docker-compose.yml`, dan instalasi binary xray-core di `install-native.sh`.
- **Sinkronisasi config Xray otomatis** (`syncXrayConfig`, `ensureXrayEgressPool`,
  `getXrayLinks`, `encodeXrayState`/`decodeXrayState`) dihapus dari `internal/admin`.
- **UI terkait Xray dihapus**: panel "Integrasi Xray-Core: VLESS Reality Stealth
  Tunnel" di halaman Settings, kartu Xray di Dashboard, dan preset Xray SOCKS5/HTTP
  di form Egress (form manual proxy tetap utuh).
- Fungsi `security.XrayStateAAD()` dihapus bersama cabang rotasinya.

### Keamanan

- **Permukaan SSRF Docker dipersempit**: entri hostname `xray` dihapus dari
  `UPSTREAM_ALLOWED_PRIVATE_ADDRS` di `docker-compose.yml` dan `.env.example`
  (pengecualian khusus container xray yang tidak lagi ada). Loopback tetap
  diizinkan untuk egress pool generik.
- **Tidak ada lagi forward proxy yang dipasang atau dijalankan** oleh skrip
  deployment resmi. Sebelumnya `install-native.sh` memasang xray-core dari
  upstream `XTLS/Xray-install` dan `deploy.sh` menjalankan container xray.
- **Izin `GET /api/domain` dilonggarkan dari `settings:write` ke `settings:read`**
  (#38). Sebelumnya izin tulis diperlukan karena respons memuat tautan
  provisioning Xray yang setara kredensial. Setelah Xray dihapus, respons hanya
  berisi status infrastruktur ringan (domain, mode HTTPS, status DNS & IP
  server), sehingga cukup `settings:read`. Mutasi (`POST`/`DELETE`) tetap
  `settings:write`. (Arsitektur Single-Admin: setiap user terautentikasi adalah
  Admin penuh; perubahan ini menjaga prinsip least-privilege & konsistensi rute.)

### Tests

- **Test AAD untuk `CLIToolAAD` & `OAuthSessionAAD` ditambahkan** (#38)
  (`TestCLIToolAADDiikatKeIDTool`, `TestOAuthSessionAADDiikatKeIDSesi`).
  Kedua AAD ini adalah satu-satunya AAD settings yang masih aktif di rotasi kunci
  setelah `XrayStateAAD` dihapus, namun sebelumnya tidak punya test khusus.
  Test memverifikasi format terikat ke ID, membedakan tiap record, dan tidak
  bertabrakan dengan `CredentialAAD`/`WebhookAAD`.

### Catatan Operasional

- Pool egress lama bernama "⚡ Xray Stealth Tunnel (Local)" (jika ada di DB
  deployment Anda, dibuat oleh `ensureXrayEgressPool` versi sebelumnya) tetap
  berfungsi sebagai SOCKS5 generik dan dapat dihapus/diperbarui via dashboard
  admin. Migrasi 0013 tidak menyentuhnya.
